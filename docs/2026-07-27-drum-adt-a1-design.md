# ドラム自動採譜（ADT）A1 設計書

作成日：2026-07-27（2026-07-29 タム3レーン追加を反映）

## 目的

ドラム音源から「叩けるグルーヴの下書き（グリッド）」を自動生成し、エディタに読み込めるようにする。
本アプリの本丸（ドラム簡略化）の最後のピース。完璧な採譜ではなく、**人が2割直す前提の粗い下書き**を出す。

- **スコープ（A）**：キック/スネアの骨格＋ハイハットの粗さ（8分/16分）を**自動で**捉える。フィル・食いは自動では狙わない。
- **手法（A1）**：新規依存ゼロ。librosa/numpy内のNMF＋固定ドラムテンプレートで KK/SN/HH を分離。
- **発動（1）**：エディタのボタンから。非破壊（既存の履歴スタックに乗る）。
- **タム3レーン（HT/MT/FT）＝表現のみ**：グリッド・エディタ・譜面にタムを足し、**人が手入力**できるようにする。
  タムのフィルは人がエディタで足す。**ADTの自動検出はKK/SN/HHのまま**（タムはスネアと音域が近くNMFでの区別が
  不安定なため、自動検出には踏み込まない）。
- **段階戦略**：まずA1を作りRebound素材で評価。明らかに力不足なら専用モデル（A2）に上げる判断をする。

CLIパイプラインへの接続は今回やらない（YAGNI。純関数で作るので後から再利用可能）。

## 出口の前提（既存資産）

ADTの出力先はすでに整備済み。ADTの仕事は **ドラムWAV → グリッド辞書** の1点に集約される。

- グリッド模型（`app/grid.py`）：`{"tempo", "bars", "steps_per_bar": 16, "lanes": {...}}`。各レーンはステップごとの 0/1 リスト。
  - **レーンは6本に拡張**：`HH / HT / MT / FT / SN / KK`（HT=ハイタム, MT=ミッドタム, FT=フロアタム）。
    全グリッドが常にこの6レーンを持つ（ADT出力・テンプレ・保存グリッドすべて）。
- 下流（エディタ表示→升目編集→まとめ簡略化→「スコア用に保存」→ score_all 自動拾い）は既存。
- 現状 `app/analyze.py build_template_from_audio()` が汎用8ビートのテンプレを返しているだけ。ここに「実演奏から起こす」経路を足す。

## 構成ユニット（責務分離）

### 1. `app/drum_transcribe.py`（新規・中核）

純関数寄り。Flask/Demucs に依存しない（呼び出し側が分離済みWAVを渡す）。依存は librosa/numpy（既存）のみ。

```
transcribe_drums(drum_wav_path, tempo, bars, steps_per_bar=16) -> grid(dict)
```

処理：

1. **グリッド時刻の生成**：tempo・bars・steps_per_bar から、各ステップの時刻（秒）を作る。1小節=4拍=4×(60/tempo)秒、1ステップ=小節長/steps_per_bar。
2. **KK/SN：準教師ありNMF**
   - ドラム音のマグニチュード・スペクトログラムを、**固定の周波数テンプレートを基底 W** として NMF（W固定・活性 H のみ学習）で分解する。
   - テンプレート（初期版・帯域強調）：
     - キック＝低域中心（〜120Hz付近を強調）
     - スネア＝中域＋広帯域ノイズ（150〜400Hz＋高域のノイズ成分）
     - ハイハット＝高域中心（6kHz以上を強調）
   - 各成分の活性 H からオンセット・ピークを検出（`librosa` のピーク検出）。ピーク強度に**しきい値**を設けてゴースト/にじみを除去。
3. **量子化**：検出した各オンセット時刻を最近傍の16分グリッドステップに吸着し、KK/SN レーンの該当ステップを 1 にする。同一ステップの重複は 1 に丸める。
4. **HH：密度から規則化**（1発ずつ拾わない）
   - ハイハット成分の活性から、優勢な刻みが**8分か16分か**を判定（例：オンセット間隔の中央値／小節あたりの打点数で分類）。
   - 判定した細かさで **規則パターン**を全小節に敷く（8分＝2ステップおき、16分＝毎ステップ）。無音に近ければ HH は空。
5. **タムは空**：HT/MT/FT レーンを全0で含める（ADTはタムを自動検出しない。人がエディタで足す）。
6. grid.py 互換の6レーン辞書を返す。

このユニットが持つべき小さな純関数（テスト対象）：
- `quantize_onsets_to_grid(onset_times, step_times) -> [step_index...]`
- `remove_ghost(peaks, strengths, threshold) -> peaks`（しきい値未満を除去）
- `infer_hihat_subdivision(hh_onset_times, bars, tempo) -> 8 | 16 | None`
- `fill_regular_hihat(subdivision, bars, steps_per_bar) -> [0/1...]`

### 1b. `app/grid.py`（タム3レーン追加）

- `make_template_grid`：HT/MT/FT を**全0**で追加（基本8ビートにタムは無い）。返す `lanes` は6本。
- `LANE_NOTATION`：タムの記譜位置を追加（通常符頭 `None`）。ドラム譜慣習でラックタムはスネアの上・
  フロアタムは下。上から音の高い順に並ぶ：
  - HH＝G5（×符頭・既存）／ **HT＝E5**（第4間）／ **MT＝D5**（第4線）／ SN＝C5（既存）／
    **FT＝A4**（第2間）／ KK＝F4（既存）
- `grid_to_score`：**欠けたレーンに寛容化**（`grid["lanes"].get(lane)`、None ならスキップ）。手組みグリッドの
  テストや、レーン欠けの古い保存グリッドが KeyError で落ちないように。
- `fit_grid_to_bars` は `lanes.items()` を回すので追加変更不要（自動で6レーン対応）。

### 2. `app/analyze.py`（配線）

```
transcribe_drum_from_audio(audio_path) -> grid(dict)
```

既存の `separate_drum_stem(audio, out_dir)` でドラム分離 → `detect_tempo` でテンポ → `count_bars` で小節数 → `transcribe_drums` を呼ぶ。分離済みドラムWAVがあれば再利用（Demucsを飛ばす）。

### 3. `app/server.py`（新ルート）

```
POST /auto-draft  ->  {grid}
```

現在曲のドラム音源に対して `transcribe_drum_from_audio` を走らせ、グリッドをJSONで返す。
- ドラム音源が見つからない/分離失敗 → HTTP 400 ＋ 日本語メッセージ「ドラム音源が見つかりません」。
- 既存ルート（`/simplify`・`/save-grid` 等）と同じ登録様式。

### 4. エディタUI（`app/templates/editor.html` / `app/static/editor.js` / `app/static/editor.css`）

- **6レーン表示**：`LANES = ["HH","HT","MT","FT","SN","KK"]`（上から）。タムは升目クリックで手入力（既存と同じ操作）。
- **ラベルを日本語化**：略号だとタムが分かりにくいので、ラベル対応（ハイハット/ハイタム/ミッドタム/フロアタム/
  スネア/キック）を持たせる。
- ボタン「**自動下書き（音源から）**」を追加。
- クリック時：現グリッドを**履歴スタックに積む**（＝既存「↩元に戻す」で戻せる）→ `POST /auto-draft` → 返ったグリッドに差し替え → 譜面を自動再描画。
- 処理は数秒かかるためローディング表示（ボタン無効化＋「解析中…」）。
- 打点検出ゼロ（空グリッド）の場合は「打点を検出できませんでした」を表示し、差し替えはしても非破壊（元に戻せる）。
- ADTの下書きはタムが空なので、タムのフィルはここで人が足す。

## データフロー

```
音源 →(Demucs)→ ドラムWAV →(NMF: KK/SN/HH成分)→ 成分ごとのオンセット
   →16分グリッドに量子化＋しきい値→ grid → POST /auto-draft
   → エディタが差し替え（履歴に積む）→ 人が升目で直す → 「スコア用に保存」→ score_all
```

## エラー処理

| ケース | 挙動 |
|---|---|
| ドラム音源なし/分離失敗 | HTTP 400 ＋ 日本語メッセージ |
| テンポ検出失敗（0.0） | 既存 `detect_tempo` の120BPMガードを流用 |
| 打点検出ゼロ（ほぼ無音） | 空グリッド（全0）を返し、UIで「打点を検出できませんでした」表示 |
| 差し替え | 常に非破壊（履歴スタック経由） |

## テスト方針

ADTは本質的に曖昧なので、**断定テストは純関数に限定**する。採譜の当たり外れ自体はテストで縛らない。

- 純関数（合成データ・決定的）：
  - `quantize_onsets_to_grid`：既知のオンセット時刻→期待ステップ
  - `remove_ghost`：しきい値でゴーストが落ちる/強い打点が残る
  - `infer_hihat_subdivision`：8分相当/16分相当/無音の入力→8/16/None
  - `fill_regular_hihat`：8→2ステップおき、16→毎ステップ、bars分の長さ
- タム3レーン：`make_template_grid` が6レーン（HT/MT/FT は全0）を返す／タムを置いたグリッドを
  `grid_to_score` に通すと該当レーンが正しい記譜位置に出る／`grid_to_score` がレーン欠けに寛容（KeyErrorしない）
- `/auto-draft` ルート：`transcribe_drum_from_audio` をモックして固定グリッドを返す形＋400ケース
- **実機評価（テストではなく記録）**：`output/Yvv4RVQzIFk/stems/ドラム.wav`（Rebound・キャッシュ済み）で「KK/SNの骨格が実際のグルーヴらしく出るか」を目視。A1が力不足ならA2へ上げる判断ゲート。

## 境界の明確さ

- `drum_transcribe.py`：`(音源＋tempo＋bars) → grid`。Flaskなし・Demucsなし。単体でテスト可能。
- 語彙は 6レーン（HH/HT/MT/FT/SN/KK）・16ステップ（既存グリッド模型を拡張）。ADTが自動で埋めるのは
  KK/SN/HH の3レーン、タム3レーンは人が手入力。
- NMFテンプレート設計とピーク閾値が改善の核心＝実機評価で初めて良し悪しが分かる（段階戦略の分岐点）。

## やらないこと（スコープ外）

- **タムの自動検出**（今回は表現＝手入力のみ。自動採譜はスネアと混同しやすく不安定なため見送り）
- フィル・タム回し・食いの精密採譜（A2以降で検討）
- CLIパイプラインへの接続
- ハイハットのオープン/クローズやライド等の区別（HHは1レーン）
