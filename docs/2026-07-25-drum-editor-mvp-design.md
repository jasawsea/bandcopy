# bandcopy ローカル版 MVP — ドラム簡略化エディタ 設計書

作成日：2026-07-25

## 背景・目的

バンドのドラマーが、最近の曲に多いダブルキック等の高難度技術を叩けず選曲を嫌がる。
それを解消し「ドラムだけでも簡潔に叩ける譜面」を出すのが本アプリの出発点。

全自動の簡略化ではなく、**「自動で下書きを出す → 人がグリッドで直す」対話型エディタ**にする。
人が最後に直せる前提なので、自動採譜（ADT）の精度が完璧でなくてよい＝精度の壁が要求から外れる。

最終形は全パート＋Score譜だが、本書は**その最初の1スライス（ローカルで動くドラム編集の核ループ）**を定義する。

## スコープ

### MVPでやること
- ローカル（自分のMac）で動かす。Pythonバックエンド＋ブラウザUI（localhost）。
- 入力：Mac上のドラムを含む音源ファイル（曲または一部分）。
- ドラムパートをグリッドで手編集 → ドラム譜（MusicXML）を出力。
- 分離したドラム音源を再生して耳で照合しながら編集できる。

### MVPでやらないこと（明示的に後回し）
- 曲ごとの自動採譜（ADT）による下書き生成（MVPは基本8ビートのテンプレートから開始）
- まとめ簡略化コマンド（「キック間引き」等）
- 全パートのScore統合
- PDF書き出し（MVPはMusicXMLのみ）
- アップロードUI・URL入力・公開ホスティング・複数ユーザー

### 編集範囲の方針
- **手編集するのはドラムだけ**。ベース/ギター/ボーカルは既存エンジンの簡略化楽譜＋コードを
  そのまま自動出力し、将来Scoreに束ねる（本MVPでは中心に置かない）。

## アーキテクチャ

3つの部品。各1役で、グリッドJSONという明確なインターフェースで接続する。

### 1. 解析バックエンド（既存Pythonを再利用）
- テンポ検出（既存 `detect_tempo`）
- Demucsでドラム分離（既存 `separate_stems` のドラムstem）
- **出発点グリッドを生成**：テンポに合わせた基本8ビート
  （キック1・3拍／スネア2・4拍／ハイハット8分）。既存のグルーヴ生成ロジックを流用。

### 2. ローカルWebサーバ（Python）
- エディタ画面（HTML/JS）を配信
- `GET /grid` … 出発点グリッドJSONを返す
- `POST /render` … グリッドJSONを受け取り、ドラム譜SVGを返す（既存verovioで描画）
- `GET /stem` … 分離ドラム音源(WAV)を再生用に配信
- `GET /export/musicxml` … 現在のグリッドをMusicXMLで書き出し

### 3. エディタUI（ブラウザ・HTML/JS）
- グリッド：KK/SN/HHの3段 × 16分ステップの升目。クリックで打点ON/OFF。
- トランスポート：ドラム音源の再生/停止（HTML5 audio）。
- 「譜面にする」ボタン：グリッドをPOSTし、返ってきたドラム譜SVGを表示。
- 書き出し：MusicXMLをダウンロード。

## データモデル（部品間の唯一の真実）

グリッド＝JSON。UIが編集し、描画部・書き出し部が消費する単一の真実。

```json
{
  "tempo": 86.13,
  "bars": 13,
  "steps_per_bar": 16,
  "lanes": {
    "KK": [1,0,0,0, ...],   // bars*steps_per_bar 長のビット配列
    "SN": [0,0,0,0, ...],
    "HH": [1,0,1,0, ...]
  }
}
```

## 拡張性：自動採譜（ADT）の差し込み

テンプレートも将来の自動採譜も、**どちらも同じグリッドJSONを吐く「出発点の生成器」**にすぎない。
UI・描画・書き出しは「誰が作ったグリッドか」を問わないため、自動採譜は**生成器を1つ足すだけ**で
差し込め、他は無改修。将来は「テンプレート／自動採譜」をボタンで切り替え可能。
（採譜精度を上げる中身＝NMFや専用モデルは別課題。差し込む配管は本設計で用意される。）

## データフロー

```
音源ファイル
  → [解析] テンポ検出・ドラム分離・出発点グリッド生成
  → グリッドJSON ＋ ドラム音源WAV
  → [UI] グリッド表示・音源再生
  → ユーザーが升目を編集
  → [POST /render] グリッド → MusicXML → verovio → SVG
  → [UI] ドラム譜を表示
  → [export] MusicXML 書き出し
```

## エラー処理

- ドラム分離に失敗 → メッセージ表示。手動テンポで空グリッドから編集は継続可能。
- テンポ検出がずれる → UIで手動テンポ上書き → グリッドを再レイアウト。
- 半端な曲尺 → 小節単位に切り上げてグリッド化。

## テスト

- **単体**：grid→MusicXML変換。既知のグリッドを与え、生成物にパーカッション音部記号・
  ハイハットの×符頭・各打点の五線位置が正しく入ることを検証。素材は既存Rebound音源。
- **手動**：UIで升目をトグルし、譜面が更新されること／書き出したMusicXMLがMuseScoreで
  正しく開けることを確認。

## 技術選択

- 描画は**サーバ往復方式**（既存Python verovioを再利用）。動作中コードをそのまま使え、
  実装量が激減。localhostのため遅延は無視できる。
- ブラウザ内WASM描画は、公開Webアプリ化する段で切り替える。
- サーバ実装：軽量な標準的フレームワーク（Flask等）を想定。
